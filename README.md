## Visão Geral

O **minhAi** (pronuncia-se "minha IA") é uma plataforma SaaS multi-tenant brasileira onde cada empresa cliente configura seu próprio assistente de IA com identidade visual própria, funções selecionadas, personalidade customizada e domínio personalizado (`[slug].minhai.com.br`).

**Proposta de valor:** Funcionário de IA que vende, atende e cobra 24 horas por dia.

## Arquitetura do Sistema

### Fluxo de atendimento por voz (WebApp/Totem)

```
Usuário fala
    → Google STT (Speech-to-Text)
    → /api/groq/classify (GROQ llama — classifica intenção)
        → Se função do sistema: retorna nome da função
        → Se conhecimento da empresa: passa para GPT-4o
    → /api/voice/process (GPT-4o + contexto da empresa via RAG)
    → Resposta texto
    → /api/voice/tts (Google TTS Neural pt-BR)
    → Áudio base64 → reproduzido no cliente
    → Se ação detectada: abre ActionModal correspondente
```

### Fluxo de atendimento Meta (WhatsApp/Instagram/Facebook)

```
Mensagem recebida
    → meta-webhook (orquestrador — retorna 200 imediatamente)
    → meta-message-router (debounce com message_debounce table)
    → GROQ classifica intenção
    → GPT-4o para conhecimento da empresa
    → Resposta enviada via Meta Graph API
```

### Fluxo de registro de nova função

Toda função nova deve seguir este checklist:
1. SQL migration → tabela se necessário
2. `assistant_functions` → insert com `default_enabled: false`
3. `functions-registry.ts` → entrada no registro
4. `companyHandlers.ts` → handler da função
5. `VoiceAssistant.tsx` → switch case
6. `ActionModals.tsx` → import e mapa
7. `voiceCommandDetector.ts` → triggers (se não auto-detectado)
8. `FunctionConfigModal.tsx` → formulário de configuração
9. Dashboard UI → card de configuração

## Rotas da API (Next.js)

### `/api/voice/process/route.ts` ⚠️ CRÍTICO

Processa o fluxo principal de voz:
- Recebe `formData` com: `text`, `companyId`, `sessionId`, `companyContext`, `groq_fallback_message`
- Injeta `companyContext` no `systemPrompt` ANTES de `company.system_prompt`
- Usa GPT-4o para resposta
- Retorna: `{ response, functionCall, sessionId }`

## Regras Críticas e Convenções

### ⛔ NUNCA fazer

```
- Reescrever meta-webhook/index.ts em sua totalidade
- Colocar dados fiscais em produtos_venda ou seus embeddings RAG
- Usar req.json() em Edge Functions (usar req.text() + JSON.parse())
- Usar Gemini para qualquer coisa (especialmente PDFs)
- Usar Claude como modelo de IA (sempre GPT-4o ou GROQ)
- Usar GROQ para dados da empresa — apenas classificação de intenção
- Debitars créditos no clique (sempre após ação completar)
- Cobrar créditos em handlers que chamam ferramentas-consultas (double-charge)
- Usar localStorage/sessionStorage em Artifacts
- Usar lucide-react dentro de modais slug/assistant (usar SVG inline)
- Usar window.speechSynthesis (sempre playText() para TTS)
- Chamar edge functions via fetch direto — sempre supabase.functions.invoke()
- Criar políticas RLS com USING (is_active = true) sem escopo de user_id
- Usar CREATE POLICY IF NOT EXISTS no Supabase (não suportado)
- Commitar google-services.json ou android.keystore
- Commitar pasta .gradle/ ou app/build/
```

### ✅ Sempre fazer

```
- Aplicar CORS em TODAS as respostas das Edge Functions
- Usar createAdminClient (service role) para queries server-side que precisam bypassar RLS
- Usar process.env.NEXT_PUBLIC_APP_URL em vez de window.location.origin em edge contexts
- URLs de manifesto PWA: Supabase Storage direto — nunca /_next/image (causa 400)
- Páginas dashboard com [companyId]: client components com useParams + supabase-browser
- Modais: createPortal(_, document.body) + position fixed inset-0
- Estilos de modal: inline style objects com paleta DARK/LIGHT — nunca Tailwind dinâmico
- TTS apenas em useEffect de mount do modal — nunca em registry handlers
- Aguardar params e headers() em Next.js 15 (são Promises)
- useIsMobile() hook para responsividade — nunca CSS hidden/block (SSR hydration)
- default_enabled: false para todas as funções novas
- select('*') em vez de campos específicos ao debugar dados ausentes
```

## Modelos de IA

### GPT-4o (OpenAI) — Principal

**Uso:** Conhecimento da empresa, respostas ao cliente, orçamentos, análise de imagens, PDF, geração de conteúdo

**Contexto injetado:**
1. `companyContext` (RAG — embeddings dos dados da empresa)
2. `company.system_prompt` (personalidade configurada pelo cliente)
3. Histórico da sessão

**Nunca usar para:** classificação de intenção (GROQ é mais rápido e gratuito)

### GROQ (llama-3.3-70b-versatile) — Classificador

**Uso ÚNICO:** Identificar qual função do sistema deve ser chamada

**Regra:** GROQ nunca recebe dados da empresa, produtos ou contexto de negócio. Apenas classifica a intenção do usuário em funções do sistema.

**Fallback:** Se GROQ falhar → GPT-4o assume

### Google TTS Neural

- Voz padrão: `pt-BR-Neural2-B` (masculina, natural)
- Voz alternativa: `pt-BR-Neural2-A` (feminina)
- Configurável por empresa
- Sempre via `playText()` — nunca `window.speechSynthesis`
- Só em `useEffect` de mount do modal — nunca em handlers de registro
